# 邀请码注册流程规格

编写时间：2026-05-28  
状态：待实施 / 已有后端基础能力  
目标：明确员工只能通过邀请码加入门店，老板负责生成、分享、作废邀请码。

## 一、完整流程图


## 二、邀请码格式

- 6 位大写字母 + 数字混合。
- 示例：`A3K7M2`。
- 生成规则建议：基于 `makeId("inv")` 或安全随机数生成，取后 6 位并转大写。
- 需要避免混淆字符：`O` / `0`、`I` / `1` 可按需排除。

## 三、邀请码状态

| 状态 | 含义 |
| --- | --- |
| 待加入 | 已生成，等待员工使用 |
| 已加入 | 员工已成功注册 |
| 已作废 | 老板手动作废 |
| 已过期 | 超过有效期自动失效，前端展示时可计算得出 |

UI 要求：

- 邀请码用大字号、分组间距显示，方便拍照或复制。
- 有效期和角色必须明确显示。
- 复制成功要用 Toast，不用浏览器 alert。
- 已作废或已使用的邀请码不能再复制为有效码。

```text

│                                  │

│ 邀请码由老板在管理中心生成          │
│                                  │
│ 邀请码：[____________]             │
│ 姓名：  [____________]             │
│ 密码：  [____________]             │
│                                  │
│ [ 加入门店 ]                       │
│                                  │
│ 已有账号？返回登录                 │
└──────────────────────────────────┘
```

UI 要求：

- 不出现“员工自行注册”的表达。
- 副文案必须说明邀请码来源：由老板或授权管理人员生成。
- 错误提示必须清晰，例如“邀请码已过期”“邀请码已被使用”“邀请码不存在”。
- 成功后自动进入对应角色首页。

## 八、邀请记录列表

| 员工 | 账号 | 角色 | 邀请码 | 状态 | 有效期 | 操作 |
| --- | --- | --- | --- | --- | --- | --- |
| 小李 | 138xxx | 美容师 | A3K7M2 | 待加入 | 2026-06-04 | 作废 |
| 小王 | 139xxx | 前台 | B5H9N4 | 已加入 | 2026-06-01 | - |
| 小张 | 137xxx | 店长 | C7J2P6 | 已作废 | - | - |

规则：

- 待加入：可复制、可作废。
- 已加入：不可作废，不可重复使用。
- 已作废：不可复制为有效码。
- 已过期：前端显示过期，不允许继续使用。

## 九、校验规则

生成邀请码：

- 角色必填。
- 登录账号必填。
- 登录账号不能与现有账号重复。
- 有效期必须大于 0 天，默认 7 天。

使用邀请码：

- 邀请码必填。
- 姓名必填。
- 密码必填。
- 邀请码必须存在。
- 邀请码状态必须是「待加入」。
- 当前时间必须早于过期时间。

## 十、实现边界

- 后端逻辑已经具备基础能力，前端需要强化体验和文案。
- 邀请码是员工进入系统的唯一正式路径。
- 老板注册门店和员工加入门店必须明确区分。
- Admin 超级管理员不走邀请码流程。
