# UI 功能边界与后续扩展备注

更新日期：2026-06-02  
当前版本：0.1.38  
状态：当前功能边界和后续扩展说明。

## 总体结论

当前基础版已经完成 Admin 端主要页面的 UI 框架、视觉统一和平台管理主链路。Admin 端聚焦平台账号、门店、邀请码、权限、审计、系统配置、通知和用量监控；预约、收银、客户等具体门店业务仍由门店端角色执行。

代码里有两类页面：

- `Platform*ReadOnlyView`：平台 Admin 看到的页面，当前主要用于跨门店总览、统计、列表展示和平台监管，不直接代替门店端业务操作。
- `Appointments` / `Pos` / `Customers` 等门店端页面：已有一部分真实业务操作，给老板、主管、前台、员工等角色使用。

当前原则：基础版 Admin 只做平台管理，不直接操作门店业务。若后续要让 Admin 代操作预约、收银、客户，需要单独评审权限边界和审计规则。

## 工作台

相关组件：`PlatformAdminView`

已完成：

- 平台工作台 UI。
- 顶部 hero。
- 核心数据卡片。
- 快捷入口。
- 营业提示和平台数据概览。

当前状态：

- 快捷入口可进入账号、权限、日志、用量、系统配置、各业务监管页。
- 门店老板申请审批已接入权限审批页。
- 门店启用、停用已接入账号管理页。
- 系统配置、账号启停、通知状态、审计筛选和导出已接入。

待扩展：

- 平台待办队列还可以继续聚合门店申请、异常用量、通知和关键审批。
- 没有系统健康状态、异常告警、API 状态等后台运维数据。

## 预约

相关组件：`PlatformAppointmentsReadOnlyView`

已完成：

- 预约记录 UI。
- 今日预约看板。
- 预约状态统计。
- 线上预约申请展示。
- 全部预约列表。

当前边界：

- Admin 页面不能新增预约。
- Admin 页面不能确认、到店、完成、取消预约。
- Admin 页面不能改期。
- Admin 页面不能把线上预约申请转成正式预约。
- Admin 页面不能安排员工排班或不可约时间。

已有可复用能力：

- 门店端 `Appointments` 组件里已有新增预约、状态更新、改期、取消、排班、不可约时间、线上预约转预约等逻辑。

## 收银

相关组件：`PlatformOrdersReadOnlyView`

已完成：

- 订单与收款记录 UI。
- 今日收银看板。
- 支付方式汇总。
- 最近订单。
- 收银提示。
- 订单流水。

当前边界：

- Admin 页面不能开单。
- Admin 页面不能选择客户、项目、员工和支付方式。
- Admin 页面不能会员卡扣款。
- Admin 页面不能退款。
- Admin 页面不能打印小票。
- Admin 页面不能发起或处理收银相关审批。

已有可复用能力：

- 门店端 `Pos` 组件里已有开单收银、会员卡扣款、审批、退款、小票打印等逻辑。

## 客户

相关组件：`PlatformCustomersReadOnlyView`

已完成：

- 客户会员资产 UI。
- 客户资产看板。
- 客户分层。
- 最近客户。
- 客户提醒。
- 客户标签。
- 会员卡概况。
- 客户列表和会员卡列表。

当前边界：

- Admin 页面不能新增客户。
- Admin 页面不能编辑客户资料。
- Admin 页面不能管理客户标签。
- Admin 页面不能开卡、充值、冻结、解冻、延期、转卡、退卡。
- Admin 页面不能新增护理服务记录。
- Admin 页面不能生成客户签名单。
- Admin 页面不能完成回访。

已有可复用能力：

- 门店端 `Customers` 组件里已有客户建档、标签、分销关系、会员卡、服务记录、签名单、回访等部分操作。

## 管理中心

相关组件：`ManagementCenter`

已完成：

- Admin 管理中心 UI。
- 顶部账号信息。
- 系统邀请码展示、隐藏、复制。
- 头像和个人资料设置入口。
- 退出登录。
- 老板邀请码生成、申请审批、列表和状态流转。
- 平台账号启用、停用。
- 门店启用、停用。
- 操作审计搜索、筛选和 CSV 导出。
- 系统配置保存到后台配置表。

待扩展：

- 权限配置目前是固定角色边界，不支持自定义角色权限模板。

## 顶部通知和头像

已完成：

- 铃铛和头像固定在顶部。
- 点击头像显示账号菜单。
- 点击空白处可关闭菜单。
- 账号设置里可以修改名字和头像。
- 通知按角色和员工可见范围过滤。
- 单条已读、全部已读。
- 全部、未读、已读筛选。
- 单条归档。

## 后续建议顺序

1. 若要继续增强 Admin，优先做平台待办队列和系统异常告警。
2. 若要让 Admin 代操作门店业务，先评审权限边界，再复用门店端预约、收银、客户逻辑。
3. 权限配置可从固定角色升级为可配置角色模板。
4. 报表可继续扩展多门店对比、趋势和导出。

## 暂不需要恢复的模块

基础版继续不要加入：

- 优惠券。
- 拼团。
- 秒杀。
- 复杂营销活动。
- 过度 SaaS 商业化模块。
