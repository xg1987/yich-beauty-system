# UI 已完成但功能未完成备注

更新日期：2026-06-01  
当前版本：0.1.22  
状态：给后续开发同事接手用的功能缺口说明。

## 总体结论

当前基础版已经完成 Admin 端主要页面的 UI 框架和视觉统一，但部分页面仍是只读看板，还没有接完整业务操作。

代码里有两类页面：

- `Platform*ReadOnlyView`：平台 Admin 看到的页面，当前主要用于总览、统计、列表展示。
- `Appointments` / `Pos` / `Customers` 等门店端页面：已有一部分真实业务操作，给老板、主管、前台、员工等角色使用。

后续开发时需要先确认一个原则：Admin 是否只做平台管理，还是也允许直接操作门店业务。建议基础版里 Admin 先聚焦账号、门店、邀请码、权限和审计；预约、收银、客户的具体业务操作优先放到门店端角色页面。

## 工作台

相关组件：`PlatformAdminView`

已完成：

- 平台工作台 UI。
- 顶部 hero。
- 核心数据卡片。
- 快捷入口。
- 营业提示和平台数据概览。

未完成：

- 快捷入口目前主要是页面跳转，不是完整业务流。
- 没有待办处理队列。
- 没有门店开通、停用、审批等直接操作。
- 没有系统健康状态、异常告警、API 状态等后台运维数据。

- 预约状态统计。
- 线上预约申请展示。

## 顶部通知和头像

已完成：

- 铃铛和头像固定在顶部。
- 点击头像显示账号菜单。
- 点击空白处可关闭菜单。
- 账号设置里可以修改名字和头像。

未完成：

- 通知中心目前偏展示，未完成全部消息状态管理。
- 没有按角色细分通知规则。
- 没有通知已读、归档、筛选等完整能力。

## 后续建议顺序

1. 先补 Admin 管理中心：门店老板邀请码生成、邀请码列表、作废、老板账号列表。
2. 再补账号和权限：平台账号、老板账号、主管、员工、前台账号的角色权限边界。
3. 再决定 Admin 是否需要直接操作预约、收银、客户。如果需要，优先复用门店端现有逻辑。
4. 最后补通知、审计、报表、系统配置等管理能力。

## 暂不需要恢复的模块

- 优惠券。
- 拼团。
- 秒杀。
- 复杂营销活动。
- 过度 SaaS 商业化模块。
