# UI 功能边界与后续扩展备注

更新日期：2026-06-02  
当前版本：0.1.72
状态：当前功能边界和后续扩展说明。

## 总体结论

当前基础版已经完成 Admin 端主要页面的 UI 框架、视觉统一和平台管理主链路。Admin 端聚焦平台账号、门店、邀请码、权限、审计、系统配置、通知和用量监控；预约、收银、客户等具体门店业务仍由门店端角色执行。

代码里有两类页面：

- `Platform*ReadOnlyView`：平台 Admin 看到的页面，当前主要用于跨门店总览、统计、列表展示和平台监管，不直接代替门店端业务操作。
- `Appointments` / `Pos` / `Customers` 等门店端页面：已有一部分真实业务操作，给老板、主管、前台、员工等角色使用。

当前原则：基础版 Admin 只做平台管理，不直接操作门店业务。若后续要让 Admin 代操作预约、收银、客户，需要单独评审权限边界和审计规则。

## 工作台

相关组件：`PlatformAdminView`

已完成：

- 平台工作台 UI。
- 顶部 hero。
- 核心数据卡片。
- 快捷入口。
- 营业提示和平台数据概览。

当前状态：

- 快捷入口可进入账号、权限、日志、用量、系统配置、各业务监管页。
- 门店老板申请审批已接入权限审批页。
- 门店启用、停用已接入账号管理页。
- 系统配置、账号启停、通知状态、审计筛选和导出已接入。

待扩展：

- 平台待办队列还可以继续聚合门店申请、异常用量、通知和关键审批。
- 没有系统健康状态、异常告警、API 状态等后台运维数据。

## 预约

相关组件：`Appointments`

- 今日预约看板。

## 管理中心

相关组件：`ManagementCenter`

已完成：

- Admin 管理中心 UI。
- 顶部账号信息。
- 系统邀请码展示、隐藏、复制。
- 头像和个人资料设置入口。

## 顶部通知和头像

已完成：

- 铃铛和头像固定在顶部。
- 点击头像显示账号菜单。
- 点击空白处可关闭菜单。
- 账号设置里可以修改名字和头像。
- 通知按角色和员工可见范围过滤。
- 单条已读、全部已读。
- 全部、未读、已读筛选。
- 单条归档。

## 后续建议顺序

1. 若要继续增强 Admin，优先做平台待办队列和系统异常告警。
2. 报表可继续扩展多门店对比；当前订单、客户和员工数据尚未带门店归属字段。

## 暂不需要恢复的模块

基础版继续不要加入：

- 优惠券。
- 拼团。
- 秒杀。
- 复杂营销活动。
- 过度 SaaS 商业化模块。
